# Step 02: AGP Classpath & Android Resource Resolution

*Phase*: 3 — Shippable Compositor Gradle Plugin  
*Status*: Complete 🟢  
*Target Module*: `plugin`

---

## 1. Objective
Hook into the Android Gradle Plugin (AGP) APIs to automatically resolve the target module's compiled `.class` files, dependency classpath, merged Android resources (`R.jar` / `res/`), and target Android SDK platform directory.

---

## 2. Architectural Design & Responsibilities
* **AGP Variant Inspection**:
  * Access the modern `AndroidComponentsExtension` on the project.
  * Listen for the `debug` build variant (or active user-selected variant).
* **Classpath Extraction**:
  * Resolve the module's compile classpath artifacts (`ArtifactType.CLASSES_JAR` or runtime classpath).
  * Resolve compiled Kotlin class outputs from `compileDebugKotlin`.
* **Android Resource Merging Integration**:
  * Wire dependencies so Compositor accesses merged Android resources generated by AGP's `processDebugResources` task.
  * Locate the module's generated `R.jar` and merged resource directory.
* **Android SDK Resolution**:
  * Extract the compile SDK version (e.g. `android-35`) and locate the corresponding `android.jar` and LayoutLib data directory in the user's Android SDK.

---

## 3. High-Level Integration Guidance
* Avoid using internal AGP classes; rely on public `AndroidComponentsExtension` and `Artifacts` APIs to ensure compatibility across AGP 8.x and 9.x.
* Package these resolved paths into an immutable `CompositorProjectContext` model passed to the daemon.

---

## 4. Verification & Quality Gates
* **Functional Test**: Use `GradleRunner` on a mock Android module to verify that `CompositorProjectContext` correctly extracts non-empty classpath entries and valid Android SDK paths.
